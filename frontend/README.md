# ПРИНТЕРА — фронтенд онлайн-типографии

Фронтенд сайта типографии (88 страниц, 29 калькуляторов, онлайн-конструктор фотокниг).
Бэкенд разрабатывается отдельно — фронт работает против задокументированных API-контрактов
(на этапе разработки — через моки).

Полная проектная документация и ТЗ — в папках `Пакет ТЗ/`, `Макеты страниц/`, `Макеты калькуляторов/`.

## Стек

- **Next.js 14 (App Router) + TypeScript** — SSR/SSG ради SEO и Core Web Vitals
- **Tailwind CSS + CSS-переменные** — дизайн-токены, две темы (тёмная PrintOS + светлая)
- **Radix UI** — доступные примитивы (Dialog, Accordion, Tabs) под WCAG 2.1 AA
- **next-themes** — переключение тем без FOUC
- **lucide-react** — иконки (инлайн-SVG)

Планируется к подключению по мере фаз: TanStack Query (калькуляторы), Zustand + History API
(состояние/URL), React Hook Form + Zod (формы), react-konva + @dnd-kit + Uppy (конструктор
фотокниг), MSW (моки API), Vitest + Playwright (тесты).

## Запуск

```bash

npm run typecheck

```

## Backend

Backend (NestJS) живёт отдельно в корне проекта — `D:\photo-print` — и поднимается на
`http://localhost:3000` (см. там `.env`, `PORT=3000`). Frontend и backend по умолчанию
претендуют на один и тот же порт 3000, поэтому при совместном локальном запуске
frontend-dev-сервер нужно стартовать на другом порту:

```bash
npm run dev -- -p 3001
```

URL backend API задаётся через `.env.local` (создаётся локально, не коммитится):

```env
NEXT_PUBLIC_API_URL=http://localhost:3000/api/v1
```

Подключение этого URL к конкретным API-вызовам — отдельная задача (на момент написания
фронт работает против моков/контрактов, реальные fetch-вызовы к backend ещё не добавлены).

## Архитектура

88 страниц схлопываются в ~12 шаблонов; 29 калькуляторов — это один движок + 29 конфигов.

```
src/
  app/                 # маршруты App Router, robots.ts, sitemap.ts, layout, 404
  components/
    navigation/        # хедер (3 слоя), мегаменю, мобильное меню, футер
    seo/               # JSON-LD (Organization, WebSite, Breadcrumb, FAQ)
    ui/                # дизайн-система: Button, Container, Section, ...
  data/                # модель навигации, футера, контент страниц
  lib/                 # site config, утилиты, SEO-хелперы
```

**Принципы:**
- Все ссылки навигации присутствуют в SSR-HTML; мегаменю скрывается через CSS (требование SEO).
- Семантические токены (`bg`, `surface`, `fg`, `primary`, …) → переключение темы «бесплатно».
- Цены считаются на бэкенде; фронт-калькуляторы собирают параметры и рендерят ответ API.

## Вопросы к согласованию (нашли при анализе ТЗ)

1. **Глубина URL**: вложенные (структура.xlsx) vs плоские (ТЗ навигации + редиректы). Принято: **плоские ЧПУ** с 301 с вложенных.
2. **GET-параметры калькулятора**: индексируемость закрыта через `canonical → базовый URL` + `Disallow: /*?`.
3. **pushState vs replaceState**: принято `pushState` (профильное ТЗ по URL калькуляторов).
4. **Схема опций калькулятора**: предложить бэкенду `GET /api/v1/calculator/{service_id}/schema` (параметры + матрицы совместимости + дефолты), чтобы не дублировать логику.
5. **Город/бренд**: в ТЗ встречаются и Москва, и Санкт-Петербург — уточнить у заказчика.
