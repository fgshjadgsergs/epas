# Демонстрация: расчёт и серверная корзина

Сценарий на 5–7 минут. Показывает, что цена и состав корзины считаются
на сервере, а не в браузере.

## Перед показом

```bash
docker compose up -d                 # postgres, backend, minio, redis
npm run seed                         # каталог услуг
npm run seed:calculator-demo         # демо-калькуляторы (isDemo, прайс DRAFT)
```

Активировать демо-прайсы в dev (в production это запрещено кодом):

```sql
UPDATE price_lists SET status = 'ACTIVE', "publishedAt" = now() WHERE status = 'DRAFT' AND "isDemo";
```

Фронтенд:

```bash
cd frontend
# .env.local
NEXT_PUBLIC_API_URL=http://localhost:3000/api/v1
NEXT_PUBLIC_DEMO_PRICING=true        # включает пометку «демонстрационный прайс»
npm run dev
```

Начать с чистой корзины: открыть `/korzina/` → «Очистить» либо новое окно
браузера (анонимная сессия живёт в cookie `kp_cart_sid`).

## Сценарий

**1. Настроить листовки.** Открыть `/listovki/`. Поменять формат на A4,
бумагу на офсет 80 г, тираж 1000. Цена пересчитывается после каждого
изменения — запрос уходит на сервер.

**2. Показать URL и серверную цену.** В адресной строке появились
параметры (`?format=A4&paper=offset-80&qty=1000`) — ссылкой можно
поделиться, расчёт восстановится. Открыть DevTools → Network → `calculate`:
цена приходит от backend, в браузере она не считается. Под ценой — пометка
«Стоимость рассчитана по демонстрационному прайсу».

**3. Добавить в корзину.** Кнопка «Загрузить макет и заказать».
В Network видно два запроса: `calculate/confirm` (сервер фиксирует
расчёт и создаёт снимок) и `cart/items` — в теле только
`calculationSnapshotId`, никакой цены. Счётчик в шапке стал `1`.

**4. Перезагрузить страницу.** F5 на `/korzina/`. Позиция на месте:
корзина хранится в базе, а не в localStorage. Можно открыть DevTools →
Application → Local Storage и показать, что корзины там нет.

**5. Добавить баннер.** Перейти на `/shirokoformat/bannery/`, задать
размер 2×1 м, добавить в корзину.

**6. Две позиции и серверный итог.** В корзине две строки со сроком
изготовления и своей ценой. «Итого» приходит из ответа сервера —
браузер суммы не складывает (видно в ответе `GET /cart`: `totals.total`).

**7. Удалить позицию.** Корзина отдаёт новый состав и новый итог,
счётчик в шапке обновляется.

**8. Войти в аккаунт.** `/lichnyy-kabinet/vhod-registraciya/` →
зарегистрировать нового пользователя.

**9. Merge анонимной корзины.** Сразу после входа выполняется
`cart/merge`: позиции, добавленные анонимно, переносятся к пользователю.
Открыть `/korzina/` — состав сохранился. Повторный вход не создаёт
дублей (merge идемпотентен).

## Что подчеркнуть

- Цена никогда не приходит с фронтенда: в `cart/items` уходит только
  идентификатор подтверждённого расчёта.
- Корзина переживает перезагрузку и смену вкладки — она в базе.
- Позиция помечается как устаревшая, если прайс изменился после
  добавления; сумма при этом молча не меняется, есть кнопка «Пересчитать».
- Оформление заказа намеренно отключено — это следующий этап; фиктивные
  заказы не создаются.

## Известные ограничения демо

- Цены демонстрационные (боевого прайса ещё нет), поэтому в интерфейсе
  стоит соответствующая пометка.
- Оформление заказа, доставка, оплата и промокоды не реализованы.
- Конструктор фотокниг пока не переведён на серверный расчёт — заказ
  оттуда отключён.
